## 1. 项目定位

《校园大冒险》当前已经不是单一玩法 Demo，而是一个可完整游玩的 2D 校园生活冒险原型。  
从代码结构和内容规模看，它同时融合了 5 条产品线：

1. `校园生活模拟`：时间、天气、季节、课程、节日、睡觉过日、家与小镇往返。
2. `关系养成`：大量 NPC、好感阶段、生日、送礼、邀约、日常闲话。
3. `学习成长`：答题、错题本、知识树、阅读、摘抄、日记、课程表。
4. `轻奇幻冒险`：回合战斗、武学、魔法、三章主线、后山/学院/时光回廊。
5. `精灵收集对战`（新）：精灵小筑采购、草丛遭遇、三系克制画布对战、GBA 式捕捉与收服簿记、
   驯兽知识（讲堂/讨教）与知识树实战反哺。

从气质上看，它已经具备“星露谷的循环感 + 我的暑假的日常感 + 校园题材奇幻化”的基础。

## 2. 当前已实现的设计骨架

### 2.1 世界结构

- 主场景已经覆盖 `家 -> 小镇 -> 校园 -> 特殊区域` 的完整闭环。
- 当前地图规模已达到 `67 张`（maps.js 构建器注册表逐一点名：校园建筑群、小镇商铺内景 ×9、
  家园群（栖霞小区 + 好友家 ×8）、西郊田野/四季广场/果园农场群、三章剧情群等），
  不是单校园平面，而是带有章节拓展空间的世界。
- 小镇主街南段新开第四家店面 **精灵小筑**：立面挂「精灵小筑」匾额（plaque 瓦片）、
  店内独立房间 `petShopIn`、店员 **阿橘** 常驻；栖霞小区两扇南门顺势改道小镇南口，
  家 → 小镇 → 精灵小筑的动线保持顺畅。
- 代码中已经明确拆出了地图、引擎、UI、剧情、成长、收集、学习等模块，扩展性不错。

### 2.2 核心循环

当前可归纳为 3 层循环：

1. `日循环`
   - 出门探索
   - 对话/收集/小游戏/课程
   - 草丛遭遇 → 画布宠物对战（捕捉 / 随行 / 逃跑）
   - 精灵小筑补耗材（宠物球 / 精灵口粮）、逛珍稀精灵架、卖多余个体
   - 打卡或推进事件
   - 夜晚复习/写日记/睡觉过日

2. `周循环`
   - 周五周测、体育节、专题事件
   - 周末野餐、重复活动刷新
   - 社团、委托、日常奖励重置

3. `章节循环`
   - 第一章：校园主线与四枚徽章
   - 第二章：月光学院与魔法课程
   - 第三章：时光回廊与毕业礼

### 2.4 精灵对战与宠物店（2026-09-20 落地）

**s9 精灵小筑（店铺线）**

- 三入口：`买耗材`（三档宠物球 + **精灵口粮** 25 文）、`珍稀精灵架`、`收购台`。
- 珍稀精灵架：以**日期为种子**的确定性刷新，每次 2~3 格、当日不重复；买走即挂 `gone` 标记，
  当日重进店不复活，跨天自动补货——货架是“每日限定”而非随机池。
- 价格体系：按稀有度 1~3 档，买入 40 / 120 / 300 文、收购 12 / 30 / 80 文，
  **异色（闪光）个体收购价 ×3**；每种当日仅此一只；已随行的伙伴禁止出售。
- 收购台鼓励“抓了卖钱”的循环，同时用球与口粮的高频消耗做经济对冲。

**s10 战斗强化（battle.js 重构）**

- **MOVES 招式注册表**：22 个招式统一登记（威力 / PP / 类型）；基础攻击 `strike` 常备（PP 99），
  武学、魔法、挚友技全部迁入注册表，效果与消耗一处可查。
- **四键菜单**：`攻击 / 防御 / 道具 / 逃跑`；攻击下再选招式（武术 / 咒语两栏子菜单）。
- **防御读招博弈**：防御时选**武防**（减伤 = 防御值）或**魔防**（减伤 = 防御 ×0.5 舍入）；
  敌方 AI 会“看穿”你的防御并触发反震——防守不再是纯减伤键，而是和心理博弈。
- **PP 制**：每招独立 PP，打光只能退回基础攻击，长战需要资源规划。
- **新伤害公式**：`伤害 = max(1, round(攻击 × 威力 / 12 − 减伤))`；
  逃跑成功率 `min(95%, 35% + 速度差 × 5% + 15% × 尝试次数)`，训练师战禁逃。
- **敌人数值重调**：全部 8 名 ENEMIES 血量 +20%、金币掉落 +25%，与新公式对齐。

**s11 宠物对战（wildBattle 画布化）**

- 草丛遭遇改由 battle.js `petMode` 全画布回合制：我方为**随行伙伴**，菜单 `招式 / 道具 / 逃跑`。
- **三系克制环**：虫 → 水 → 兽 → 虫，克制 ×1.5、抵抗 ×0.75；每系专属招式
  （虫鸣乱舞 / 水花射击 / 猛扑）+ 鼓劲（加攻）+ 守护（减伤），打击反馈带“效果绝佳/收效甚微”。
- **GBA 式捕捉**：`捕捉率 = min(92%, (3−2H)/3 × 60% × 球档 × (1 + 疲惫加成 + 口粮加成))`；
  球档 1.25 / 1.6 / 2.2 三档——先打残、先喂口粮再丢球更划算；球被弹开时对方还可能趁乱溜走。
- **收服簿记**：收服后可 `放归`（+3 金）或 `邀为随行`；随行伙伴参战且体力跨场携带
  （`f.wildHp`），归巢休整恢复；**无伙伴时遭遇战为“脱身战”**——招式菜单锁定，
  只能靠逃跑或丢球硬闯。
- **存档兼容**：全部新字段只增不改（`S.petShop`、`f.wildHp`、`gone` 标记等），旧档自动升级。

### 2.5 生物课 × 精灵线联动（2026-09-20 落地，一期/二期）

**s12 驯兽知识与导师**

### 2.7 玩法批次一（2026-09-21 落地，借鉴清单优先级 1+2）

> 来源：[玩法灵感清单.md](玩法灵感清单.md)。三个小件全复用 period/calendar/讨教既有系统。

- **C6 期末成长报告**：`growthReport()` 聚合全学期答题数/正确率（quizLog）、知识点、图鉴与
  累计收服、好友进度/帮助声望/连续打卡、学院分/零花钱，按 `Growth.aggregate()` 五维之最
  给定制老师评语（学识→王老师/体魄→刘老师/心性→校长/人缘→同学们/技艺→美术老师）；
  毕业仪式结局台词后播报两页（在 200 文礼金前结算），手册成长页底部常驻同源报告条。
- **C4 老师办公时间**（午休 = period 2）：`trial()` 检测后——作业全对奖励翻倍
  （8→16 文、学院分 ×2）+ 专属台词；正式试炼首错「当面重讲」错题清零一次（forgiven 旗标）。
- **C2 图书馆借书**：秦墨处 `libMenu()` 三态（借阅中/逾期/未借），借期 3 天；
  带对应课本上课（takeClass kp 结算点）知识点 +50%；按时归还 +6 文 + 科目知识点 +2；
  **偏差**：逾期不扣声望（护「小镇之光」成就线），改罚金 `min(gold,10)` 文并强制收书；

## 3. 当前设计优势

### 3.1 内容密度非常高

项目最强的一点不是“有一个好点子”，而是已经把生活系统、剧情系统、小游戏系统和成长系统接起来了，
现在又叠加了一条完整的“收集-养成-对战”精灵支线。  
这意味着它已经具备长时游玩的基础，不再依赖单点新鲜感。

### 3.2 系统之间存在联动

不是每个系统都孤立存在，而是已经有明显闭环：

- 学习会反哺战斗（错题本知识树 → 主战数值 + **宠物战四维加成**；克制环讲堂/驯兽讨教 → 捕捉与续航）
- 阅读会反哺日记和复习
- 好感会解锁剧情与战斗支援
- 日历/天气会影响活动与收集
- 精灵小筑 ↔ 宠物对战形成“金币 → 球/口粮 → 捕捉 → 收购或随行 → 再战”的小经济闭环
- 虫系个体与昆虫图鉴、斗虫擂台共用一份数据，收集与对战互相导流
- 考试成绩 → 驯兽好礼（周测/月考/期中三级），学业与精灵线互相导流

这类联动是“星露谷式黏性”的关键基础。

### 3.3 技术表达统一

纯 Canvas + 程序化像素资源让美术、地图、音频、交互风格一致，避免了素材拼贴感。  
宠物对战同样走零素材路线：`petMode` 直接复用画布战斗渲染与精灵图封装，
和主战斗、小游戏一个味儿。这对独立项目非常重要，因为统一感本身就是体验价值。

### 3.4 验证体系成熟

`tools/smoke.js` 已经覆盖到 `1081` 项断言（928 → 986 → 1005 → 1012 → 1022 → 1081）。  
其中战斗强化与宠物对战三段（[5.51] 20 条 / [5.52] 11 条 / [5.53] 21 条）、驯兽联动两段
（[5.54] 8 条 / [5.55] 11 条）、亲密度对战（[5.56] 7 条）、周末系统打磨（[5.57] 10 条）
与 s16 会话十一段（[5.58]–[5.68] 59 条）**多处直接重载真实 battle.js 模块**——
用 VM 注入临时替换战斗桩，断言完毕后在 `finally` 中完整恢复，
公式边界（伤害下限、捕捉率上限、逃跑封顶、克制倍率、petBonus 封顶、连战 tier 缩放、
催化加成）测的是真实现而不是测试替身。  
这说明项目不是“堆功能”，而是已经具备可持续迭代的工程基础。

## 4. 当前设计风险

### 4.1 核心幻想过多，容易抢戏

目前前台同时在讲 4 件事：

- 校园生活
- 学习成长
- 奇幻战斗
- 精灵收集对战

每一条都足够做成一个主游戏。现在它们都很强，结果就是玩家会感到“内容很多”，但不一定立刻抓住最核心的情绪锚点。
s16 的系统开张导览（一天开张一家）已经从「出现节奏」上控制了抢戏问题，剩下的是实机观察各系统的留存表现。

### 4.2 前 30 分钟的信息压力偏大（已大幅缓解 ✅）

s16 之前，手册、好感、收藏、打卡、课程、战斗、小游戏、主线目标都在较早阶段出现。  
**体验收束（一）已落地**：`SYSTEM_TOUR` 导览让新玩法逐日开张、任务清单新生阶段不再列出图鉴进度——
前 30 分钟稳定为「走路、认识人、打卡、睡觉」四件事。剩余工作是实机验证开张顺序的节奏手感。

### 4.3 奖励系统略显分散（呈现语言已收敛 ✅）

当前前台奖励依然很多（金币/好感/学院分/知识点/图鉴/成就/菜谱卡牌称号），但 s16 的
**体验收束（二）**已把全天收获收束进睡前结算单的「🌟 今日收获」一行，
「我今天过得真充实」有了单一体感的落点。日常散点提示仍保持轻量，后续观察是否需要进一步合并。

### 4.4 文档口径落后于实现（已处理 ✅）

本条为上一版遗留风险：README 与本总览的地图数、手册页签数、冒烟断言数均已老化。  
**2026-09-20 已按代码重新核对并统一口径**：67 张地图（maps.js 构建器注册表）、
12 页签 × 5 组（ui.js `TAB_META`）、1081 项冒烟断言（smoke.js 实跑输出）。
后续约定：统计数字一律以 smoke 实跑结果与构建器注册表为准，改代码同步改文档。

### 4.5 手册的信息架构偏工程化（已大幅缓解）

手册已从 9 页签平铺升级为 **12 页签 × 5 组**（关系 / 生活 / 收藏 / 学习 / 成长，
↑↓ 切组、←→ 组内切页），生物图鉴独立成页避免总览网格过长——工程感明显收敛。  
剩下的工作主要是前期引导（什么时候介绍哪个页），手册结构本身已不是短板。

## 5. 当前阶段的结论

精灵对战线（s9–s11）、生物课联动一期/二期（s12–s13）、剧情游戏性一期（s14，P-A 四项）、
周末系统打磨（s15），以及 s16 会话的体验收束两条 + P-B 期五项 + 驯兽三期 + 周日钓鱼大赛 +
星露谷 s5–s8 全部落地并通过回归（1081/0）。
此前 §5 提出的「设计收束」四点已按序执行完毕：

1. ✅ 明确玩家首先体验到的是什么——系统开张导览（一天开张一家）落地。
2. ✅ 把系统按“生活感 -> 关系 -> 成长 -> 奇幻高潮”重排优先级——s5–s8 生活感分期
   与 P-B 剧情二期补完，心级事件给关系养成一个情感终点。
3. ✅ 让前期体验更像在校园里生活——前 30 分钟收束为四件事，其余玩法逐日登场。
4. ⬜ 实机观察精灵线与畜牧产出叠加后的经济曲线（球价、收购倍率、放归 +3 金、
   牛奶/羊毛/帮助板酬金），必要时微调——**列入下一阶段实机走查项**。

下一阶段的重点随之切换：**工程底盘**（git 初始化、game.js 拆分、存档多槽位 + 导出导入）
与**实机验证**（浏览器 e2e、前 30 分钟节奏手感、经济曲线），而不是继续横向加系统。
